# Architecture Decision Records

Every load-bearing decision in this project is recorded here, numbered in the order it was made. Read in
sequence, they are the project's decision story. All are **Accepted**.

| # | Decision | In one line |
|---|---|---|
| [0001](adr-0001-purpose-and-core-pack-architecture.md) | Repository purpose and core/pack architecture | A vendor-agnostic `core/` measurement engine plus vendor `packs/`; two-condition mode first-class; spec availability + license scored; integrity kit carried over. |
| [0002](adr-0002-extraction-and-regression-gate.md) | Extraction method, pack manifest, and the regression gate | Vendor coupling parameterized through a declarative `pack.yaml`; a guard test proves `core/` is vendor-free; a permanent regression gate reproduces the frozen 73/68/93 tables exactly. |
| [0003](adr-0003-job-taxonomy.md) | The job-category taxonomy | A fixed, vendor-neutral set of job categories (`core/taxonomy.py`); tasks stay product-native, comparison happens at category level only; N/A is a first-class, recorded outcome. |
| [0004](adr-0004-category-cross-vendor-comparison.md) | Category-level rollup and cross-vendor comparison | `core/category.py` rolls a condition's per-task aggregate up to per-category numbers and renders a labeled `category × source` table; names no vendor, one condition fixed per table, verified against the reference pack's 1:1 map. |
| [0005](adr-0005-public-docs-fetch-fidelity.md) | public-docs models what a fetch actually retrieves | An un-fetchable page (manifest `fetch_error` or `byte_size: 0`) injects nothing instead of raising, so a vendor with a dead portal or SPA reference still runs a full grid; the forgot-to-fetch safety is preserved for pages that claim content. |
| [0006](adr-0006-factory-dispatcher.md) | The factory — an unattended, gated pipeline dispatcher | `core/factory.py` + a `factory` (next/run/status) command work a ranked queue through recon→validate→anchoring→mock→canary→grid→compare→card; every stage is a hard gate that blocks-with-reason; authoring stays external and anchoring-gated (auto-authoring deferred); names no vendor; no live vendor-API calls. |
| [0007](adr-0007-docs-fetch-user-agent.md) | A bot-gated docs host is a fetch policy, not an empty docs finding | A docs host that serves full pages to a browser agent and 404s a self-identifying one is measured on its documentation, via an opt-in `public_docs.user_agent`; the default agent stays honest, the override is recorded in the manifest, and the gate is reported as its own finding. Refines ADR-0005. |
| [0008](adr-0008-unversioned-apis.md) | An unversioned API is scored on whether the model knows it, not on which word it picked | `normalize_version` collapses every spelling of "there is no version" (`none`, `n/a`, `<none>`, …) to the empty version, symmetrically for ground truth and answer; asserting a version the API lacks still scores 0, and the frozen 73/68/93 gate is unmoved. The prompt contract's silence on the empty case is recorded as open work, not patched beside a measurement. |
| [0009](adr-0009-throttled-docs-fetch.md) | A 2xx with an empty body is a fetch failure, not a snapshot | A docs host that throttles automated readers with `HTTP 202` + 0 bytes would otherwise be recorded as a clean fetch of an empty page; `_fetch` now raises `EmptyDocument`, only throttles are retried (a 404 is a fact about the page), and packs may declare `public_docs.fetch_delay_seconds` — default 0, so no committed snapshot moves. Refines ADR-0005/0007. |
| [0010](adr-0010-ground-truth-round-trip-control.md) | A task that cannot score its own answer key is an instrument, not a measurement | Every pack must score each task's ground truth against itself, perfectly, before any grid runs — a new `roundtrip` gate between `validate` and `anchoring`, plus a CLI command and a suite-wide check over every pack on disk. Records plainly what it cannot do: an answer key always matches itself, so it detects an *unscoreable* key, never a *wrong* one. Refines ADR-0006. |
| [0011](adr-0011-auth-login-styles.md) | A dimension the scorer cannot positively test is not allowed to score | `auth_flow` recognized only bearer and client-credentials, so ground truth naming neither scored 1.0 against any answer that also named neither — and, on a task whose prose *denies* OAuth, credited the documented-wrong answer. Five login styles are now matched in an argued precedence order, and an unlisted style **blocks** the `roundtrip` gate rather than drawing a note. Scorer-only, so archives re-score offline; the frozen 73/68/93 gate and every OAuth-shaped pack are byte-identical. Refines ADR-0010, follows ADR-0008. |
| [0013](adr-0013-spec-server-prefix.md) | Where a spec ends its server URL is not where the vendor's docs start the path | An OpenAPI 3 `servers[].url` (or Swagger 2 `basePath`) may absorb any prefix of an endpoint's address, so the spec's leftover path is not necessarily the path a caller writes. The anchoring gate assumed it was, forcing ground truth into the spec's notation even when the vendor's documentation — which is what the measured model has read — drew the base URL elsewhere. A pack may now anchor a path written from any point inside the declared prefix. Found when a first grid reported `endpoint` at 13.7% while the model was right in 98% of runs; the round-trip control cannot catch it, because a key in the wrong notation still matches itself. Widens the gate only — no scorer rule changes. Refines ADR-0006, shares its subject with ADR-0008. |
| [0014](adr-0014-answer-format-repair.md) | An answer we cannot parse is not the same as an answer that is wrong | A model naming an indexed API parameter (`sortBy[0].name`) inside the single-line flow sequence **the prompt contract itself demonstrates** produces invalid YAML, and the parser discarded the whole answer — endpoint, method, version and auth along with it. One narrow repair now runs, only after YAML has already failed, only on the two list-valued keys, with quote-aware splitting and an item guard that abandons the repair rather than guess: both dimensions it can reach are containment-scored, so a bad split could only ever manufacture a score upward. Repairs are counted (`format_repairs`, always present) and the repaired text is archived. Re-applied to archives at $0; the frozen 73/68/93 reproduces, though only because the one rescued answer scored 6/6. Follows ADR-0008/0011; names a second blind spot in ADR-0010 — `render_block` emits block sequences, so the round-trip control can never speak the dialect its own parser was rejecting. |
| [0015](adr-0015-hazard-registry.md) | A recorded hazard with no gate and no queue is a note that decays | `docs/hazards.yaml` lists every recorded instrument hazard; each entry declares **gated** (naming tests that must resolve on disk) or **ungated** (naming a reason and where the fix is queued), and `core/tests/test_hazards.py` fails if it declares neither. `drift_pin` — a test that fires when a live hazard's *state* is edited — is a property of an ungated entry and never satisfies the gated requirement. Every ADR must appear in an entry or be declared hazard-free, so a new one cannot add a blind spot silently. Reports state only, changing no measurement: 14 of 47 hazards are gated, 26 are queued nowhere, and ADR-0008/0011/0014's three prompt items turn out to be one deferral behind one trigger. |

New decisions get the next number in sequence; superseded ones are marked, not deleted. **0012 was
never issued** — the sequence jumps 0011 → 0013, and no ADR by that number was ever committed.
