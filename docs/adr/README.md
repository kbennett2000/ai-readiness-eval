# Architecture Decision Records

Every load-bearing decision in this project is recorded here, numbered in the order it was made. Read in
sequence, they are the project's decision story. All are **Accepted**.

| # | Decision | In one line |
|---|---|---|
| [0001](adr-0001-purpose-and-core-pack-architecture.md) | Repository purpose and core/pack architecture | A vendor-agnostic `core/` measurement engine plus vendor `packs/`; two-condition mode first-class; spec availability + license scored; integrity kit carried over. |
| [0002](adr-0002-extraction-and-regression-gate.md) | Extraction method, pack manifest, and the regression gate | Vendor coupling parameterized through a declarative `pack.yaml`; a guard test proves `core/` is vendor-free; a permanent regression gate reproduces the frozen 73/68/93 tables exactly. |
| [0003](adr-0003-job-taxonomy.md) | The job-category taxonomy | A fixed, vendor-neutral set of job categories (`core/taxonomy.py`); tasks stay product-native, comparison happens at category level only; N/A is a first-class, recorded outcome. |
| [0004](adr-0004-category-cross-vendor-comparison.md) | Category-level rollup and cross-vendor comparison | `core/category.py` rolls a condition's per-task aggregate up to per-category numbers and renders a labeled `category × source` table; names no vendor, one condition fixed per table, verified against the reference pack's 1:1 map. |
| [0005](adr-0005-public-docs-fetch-fidelity.md) | public-docs models what a fetch actually retrieves | An un-fetchable page (manifest `fetch_error` or `byte_size: 0`) injects nothing instead of raising, so a vendor with a dead portal or SPA reference still runs a full grid; the forgot-to-fetch safety is preserved for pages that claim content. |
| [0006](adr-0006-factory-dispatcher.md) | The factory — an unattended, gated pipeline dispatcher | `core/factory.py` + a `factory` (next/run/status) command work a ranked queue through recon→validate→anchoring→mock→canary→grid→compare→card; every stage is a hard gate that blocks-with-reason; authoring stays external and anchoring-gated (auto-authoring deferred); names no vendor; no live vendor-API calls. |
| [0007](adr-0007-docs-fetch-user-agent.md) | A bot-gated docs host is a fetch policy, not an empty docs finding | A docs host that serves full pages to a browser agent and 404s a self-identifying one is measured on its documentation, via an opt-in `public_docs.user_agent`; the default agent stays honest, the override is recorded in the manifest, and the gate is reported as its own finding. Refines ADR-0005. |
| [0008](adr-0008-unversioned-apis.md) | An unversioned API is scored on whether the model knows it, not on which word it picked | `normalize_version` collapses every spelling of "there is no version" (`none`, `n/a`, `<none>`, …) to the empty version, symmetrically for ground truth and answer; asserting a version the API lacks still scores 0, and the frozen 73/68/93 gate is unmoved. The prompt contract's silence on the empty case is recorded as open work, not patched beside a measurement. |
| [0009](adr-0009-throttled-docs-fetch.md) | A 2xx with an empty body is a fetch failure, not a snapshot | A docs host that throttles automated readers with `HTTP 202` + 0 bytes would otherwise be recorded as a clean fetch of an empty page; `_fetch` now raises `EmptyDocument`, only throttles are retried (a 404 is a fact about the page), and packs may declare `public_docs.fetch_delay_seconds` — default 0, so no committed snapshot moves. Refines ADR-0005/0007. |
| [0010](adr-0010-ground-truth-round-trip-control.md) | A task that cannot score its own answer key is an instrument, not a measurement | Every pack must score each task's ground truth against itself, perfectly, before any grid runs — a new `roundtrip` gate between `validate` and `anchoring`, plus a CLI command and a suite-wide check over every pack on disk. Records plainly what it cannot do: an answer key always matches itself, so it detects an *unscoreable* key, never a *wrong* one. Refines ADR-0006. |
| [0011](adr-0011-auth-login-styles.md) | A dimension the scorer cannot positively test is not allowed to score | `auth_flow` recognized only bearer and client-credentials, so ground truth naming neither scored 1.0 against any answer that also named neither — and, on a task whose prose *denies* OAuth, credited the documented-wrong answer. Five login styles are now matched in an argued precedence order, and an unlisted style **blocks** the `roundtrip` gate rather than drawing a note. Scorer-only, so archives re-score offline; the frozen 73/68/93 gate and every OAuth-shaped pack are byte-identical. Refines ADR-0010, follows ADR-0008. |
| [0013](adr-0013-spec-server-prefix.md) | Where a spec ends its server URL is not where the vendor's docs start the path | An OpenAPI 3 `servers[].url` (or Swagger 2 `basePath`) may absorb any prefix of an endpoint's address, so the spec's leftover path is not necessarily the path a caller writes. The anchoring gate assumed it was, forcing ground truth into the spec's notation even when the vendor's documentation — which is what the measured model has read — drew the base URL elsewhere. A pack may now anchor a path written from any point inside the declared prefix. Found when a first grid reported `endpoint` at 13.7% while the model was right in 98% of runs; the round-trip control cannot catch it, because a key in the wrong notation still matches itself. Widens the gate only — no scorer rule changes. Refines ADR-0006, shares its subject with ADR-0008. |
| [0014](adr-0014-answer-format-repair.md) | An answer we cannot parse is not the same as an answer that is wrong | A model naming an indexed API parameter (`sortBy[0].name`) inside the single-line flow sequence **the prompt contract itself demonstrates** produces invalid YAML, and the parser discarded the whole answer — endpoint, method, version and auth along with it. One narrow repair now runs, only after YAML has already failed, only on the two list-valued keys, with quote-aware splitting and an item guard that abandons the repair rather than guess: both dimensions it can reach are containment-scored, so a bad split could only ever manufacture a score upward. Repairs are counted (`format_repairs`, always present) and the repaired text is archived. Re-applied to archives at $0; the frozen 73/68/93 reproduces, though only because the one rescued answer scored 6/6. Follows ADR-0008/0011; names a second blind spot in ADR-0010 — `render_block` emits block sequences, so the round-trip control can never speak the dialect its own parser was rejecting. |
| [0015](adr-0015-hazard-registry.md) | A recorded hazard with no gate and no queue is a note that decays | `docs/hazards.yaml` lists every recorded instrument hazard; each entry declares **gated** (naming tests that must resolve on disk) or **ungated** (naming a reason and where the fix is queued), and `core/tests/test_hazards.py` fails if it declares neither. `drift_pin` — a test that fires when a live hazard's *state* is edited — is a property of an ungated entry and never satisfies the gated requirement. Every ADR must appear in an entry or be declared hazard-free, so a new one cannot add a blind spot silently. Reports state only, changing no measurement: 14 of 47 hazards are gated, 26 are queued nowhere, and ADR-0008/0011/0014's three prompt items turn out to be one deferral behind one trigger. |
| [0016](adr-0016-deferred-work-has-a-destination.md) | A deferred fix now has a destination, so "not queued" has to mean something narrower | ADR-0015 allowed `fix_queued_to: "not queued"` because there was no queue to name; the cycle contract now files deferred work as a GitHub issue, so that one phrase stops covering three different states — *not closable*, *considered and declined*, and *nobody decided* — and only the third was ever a defect a registry could report. Narrows the prose, changes no field, schema or validator rule, and refuses the flattering move of opening 26 issues so every entry can cite one. The triage pass itself is filed rather than performed, because grading a decision beside the decision that authorized it is not a check. Refines ADR-0015. |
| [0017](adr-0017-endpoint-base-prefix.md) | The scorer had the same blind spot ADR-0013 fixed in the gate | ADR-0013 taught the anchoring gate that a spec's `servers[].url` is not where the vendor's docs start the path, and left the scorer comparing literally. A grid then read `endpoint` at 3% cold and 85% documented, with `method` and `api_version` moving as one — because cold answers wrote the full address the docs teach and documented answers wrote the fragment's `paths` key. Both are correct; no single literal ground truth accepts both. A pack may now declare one `endpoint_base_prefix` the scorer absorbs from either side. Opt-in and absent by default, so no other pack moves and the frozen 73/68/93 is unchanged; never derived from `base_url`, which points at a spec repository for three packs. The must-not-inflate counterexample is pinned: `/admin/users/{id}` must not match `/users/{id}`. Refines ADR-0013; names a third failure of the ADR-0010 control, which stays green because an answer key always matches itself. |

| [0018](adr-0018-prospect-names-live-outside-this-repo.md) | The leak guard was the only file naming what it protects | The guard enforcing "no tracked file names a measured prospect" listed every prospect and **exempted its own file**, so the one file excused from the rule was a better roster than any leak it prevented — in a public repo, since cycle 2. The list now loads at runtime from the private packs repo via `AIRE_PACKS_DIR`, so this repo holds **zero** names; unset skips with a message, set-but-broken or zero-names fails loudly. The self-exemption is gone and asserted gone. Widening the list found ten targets never guarded at all, and that the rule was stated wrong — an archived transcript in which the *measured model* named a third-party product forced "no file this project **authored**". |
| [0019](adr-0019-parked-is-a-status-not-a-synonym.md) | `parked` is a status, not a synonym for blocked | `parked` existed only as prose in core's own comments, so writing it into a queue entry would have made that target the **next thing the factory dispatched and spent on**, counted it as open, and dropped its reason line. `blocked` is a property of the target; `parked` is a decision about it, and collapsing them files our judgement under a vendor's shortcomings. The status vocabulary is now derived from `STAGES` and rejected at load time, so a typo can no longer read as "dispatch this next". |
| [0020](adr-0020-service-qualified-version.md) | A service-qualified version is the same version | The prompt contract offers `<service>/v1` as a legal `api_version` answer and `normalize_version` never accepted it, so on an API documented as versioned per service a model that had read the documentation answered `ledger/v1` against a ground truth of `v1` on **55 of 55** endpoints and the dimension read **1%** — a headline that would have said that vendor's docs make the model worse overall. `normalize_version` now collapses one `<service>/vN` qualifier, symmetrically; it cannot credit the wrong service, because `api_version` is only scored on an endpoint whose path already matched. The exhibit keeps what the model actually wrote — the first attempt normalized that field too and rewrote ten archived strings without moving a score, which the byte-identical regression assertion caught. Completes ADR-0013/0017 on the version axis; the contract's two spellings become the third prompt item queued behind one cohort re-run. |

| [0028](adr-0028-product-name-guard.md) | A prospect is named by what it sells | The leak guard derived every token from what a vendor is CALLED, so a public file naming four of a target's distinctive products identified it while the guard stayed green (#40). Queue entries now declare `guard_product_tokens` / `guard_product_tokens_cased`, extending rather than replacing the name tokens and returned by their own accessor. Product tokens are matched **whole-word** where vendor names are matched as substrings: unbounded, the first run reported eight false positives against one true one, and a guard that cries wolf at that ratio gets switched off. 143 tokens across 19 targets; the scan found **one** pre-existing leak (ADR-0020's illustrative literals, replaced with neutral stand-ins and disclosed in an amendment note — no assertion or number moves) and **two** written by this cycle while building the guard, both in prose explaining it. What it still cannot do: an unqueued target contributes zero tokens, which only the ordering rule covers. No scorer, parser, prompt or fixture touched; 73/68/93 unmoved. |

| [0029](adr-0029-availability-and-vendorability-are-two-findings.md) | "A spec exists" and "we may keep a copy" are two findings | The recon gate read availability and never read `permits_vendoring`, a field every pack records, so a vendor publishing a real first-party OpenAPI document under an all-rights-reserved licence had two passable encodings and both were wrong: write `no`, putting a false claim on a published card and destroying the finding the card exists to report, or commit a copyrighted file. Packs already in the cohort took the first and say so in a comment above the flag. The gate now branches on both findings: available + permitted is **unchanged byte for byte**, including its failure text, because the incoherent pack that claims a spec and ships nothing is the pipeline's one original hard failure; available + **not** permitted must NOT carry a vendored spec and must record `where` the document is. That exemption is not a waiver — with no spec file, `validate`'s anchor rule and `check_anchoring`'s resolver force **every** endpoint to be doc_ref-anchored into a manifest pinning each page by URL, byte size and hash, so writing `no` buys a hand-authored anchor per endpoint instead of one file copied once, and the theorem is pinned by a cross-gate test rather than duplicated. An unreadable value in either field now blocks in both directions, closing a pre-existing hole where a typo'd availability fell through to the doc-anchored PASS. Also lands the docs truncation audit: the budget crops the tail of the last page it keeps, and a cropped-away endpoint is indistinguishable from an undocumented one, so a sweep over every pack on disk asserts the budget never deletes a path the cached page does contain — while deliberately never requiring the docs to contain the answer. 13 packs checked, **0 moved**, both pass/fail strings byte-identical, 0 truncation losses across 138 endpoints; 73/68/93 unmoved. What it cannot do: read a vendor's terms of use. Refines ADR-0006; follows ADR-0001's separation of the two dimensions. |

| [0030](adr-0030-authorization-code-is-a-login-style.md) | The authorization-code grant is a login style, and it outranks the token it produces | `_AUTH_STYLES` named seven login styles and not the OAuth 2.0 authorization-code grant — the flow every user-context API uses. Because prose describing a grant necessarily names the credential it produces ("the resulting access token is presented as `Authorization: Bearer`"), such ground truth canonicalized to `bearer-token` while a model answering the precise "OAuth2 authorization code with PKCE" canonicalized to `unknown`: the dimension **inverted**, scoring the exact answer 0 and a vaguer one 1, in two packs on both conditions, one already published. The new style ranks **above** `bearer-token` of necessity — below it, it could never fire on a realistic key, so the fix would have repaired nothing — and **below** `oauth2-client-credentials` conservatively. Markers are phrases; bare `code` is a pinned must-not. Scorer-only, so archives re-scored at **$0, no model ran**: 2 ground-truth keys re-canonicalize and 2 published conditions move **upward** (79.1→80.6 cold, 80.8→82.3 documented) as a correction, with the affected card and the cohort table updated and disclosed. Frozen 73/68/93 unmoved. Fourth recorded failure of the ADR-0010 control: the guard fires on silence, not on being wrong. Refines ADR-0011, follows ADR-0023. |

| [0031](adr-0031-a-prompt-must-name-its-target.md) | A prompt must name its target | Every gate this project had read the ANSWER KEY — `recon`, `validate`, `roundtrip`, `anchoring`, the truncation audit — and nothing read the question. Twelve prompts saying "this vendor's API" and naming nobody passed all of them; 45 of 60 cold runs were the model correctly refusing to guess, and the grid was discarded at a cost of $9.16 after a human read one transcript. `pack.yaml` now declares `vendor_names` and `product_names`, and every task prompt must name at least one from **each** — the "and" is the ruling, because a corporate parent that sells several APIs does not say which surface is meant, and a one-list rule cannot see that. One implementation, three callers: a new `prompts` stage between `validate` and `roundtrip`, a `cmd_run` pre-flight that blocks before the transport is even built, and a standalone subcommand. Fail-closed with **no waiver mechanism at all** — no skip flag, no exemption list, no grandfathering. Whole-word matching, because as substrings short product marks occur inside *discovery* and *miscellaneous*, and a gate that passes by accident reports coverage it lacks. Dual-listing a name is permitted for a distinctive product mark and **never** for a bare corporate parent; core cannot tell them apart, so it reports every overlap and the judgement is an ungated hazard. Backfilled over all 13 packs before any code: **41 prompts across 6 packs would have failed**, the vendor half and the product half in different packs. 12 are repaired declaration-side (no prompt text, no number moves); **31 across 5 packs are genuine and left in place**, pinned by exact task id and filed. The frozen reference pack is among them — 10 of 11 prompts say only `ISC` — and is pinned rather than fixed or exempted, with `ISC` deliberately absent from its vendor names. Every pinned pack's absolute numbers are bounded by this; none of their FINDINGS are, since all conditions used identical prompts. No scorer, parser, prompt text or fixture touched; 73/68/93 unmoved. |

| [0032](adr-0032-format-failure-circuit-breaker.md) | A condition whose format-failure rate exceeds 20% stops the grid | The empirical half of ADR-0031: a prompt can name its target and still be unanswerable as asked. The discarded grid gave the signal in its own output — 45/60 format failures against a 0% sibling — and nothing acted on it, so the run completed and printed a headline better than the truth. `cmd_run` now stops the condition when the running rate exceeds a threshold after a floor. Both numbers are derived from the record, not chosen: across **26 published conditions** the widest legitimate rate is **5.5%** and the one broken question produced **75%**, so **20% is the geometric midpoint**, 3.6× above anything real and 3.75× below the case it must catch. The floor came from replaying every archive and taking the worst rate over any prefix at least that long — **20.0% at a floor of 10 (zero headroom), 13.3% at 15, 11.4% at 20** — so 20 clears the worst real prefix by 1.75× and still trips a broken grid at run 20, saving two thirds of the spend. The replay is a standing test and is deliberately pessimistic: it reads per-run flags that go stale after `rebuild-report` (3 conditions, 8 flags, filed as #52), so it replays a worse record than was published and still never fires. It is a **circuit breaker, not a verdict** — nothing is deleted or re-scored, the grid stays resumable, and it exits BLOCKED asking for a human ruling, because a model can legitimately refuse on an obscure API and that counter is recorded as an ungated hazard. `--format-failure-threshold` overrides it and the value in force is written into `scores.json` whether or not it fired, so proceeding past a high rate is a decision on the permanent record. What it cannot see: a misleading question that yields confident, parseable, wrong answers at a 0% rate. No scorer, parser, prompt or fixture touched; 73/68/93 unmoved. |
